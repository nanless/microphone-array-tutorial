Chapter-by-chapter audit baseline: 2026-09-28 (pedagogical baselines, chapter mappings, exercises, and directly referenced upstream sources across Chapters 1–11 and Appendices A/B were audited chapter by chapter; subsequently expanded to synchronize the Chapter 0 shared mathematical foundation kernels and Chapters 12–15 Frontier Topics I–IV, incorporating the Chapter 14–15 wearable/TSE baselines and 13 pure-text external source selections into the tables below, while preserving the exact historical acquisition, dependency, and execution records of earlier upstream entries). This matrix covers every method defined, derived, or evaluated for system selection in the main textbook prose, plus research extensions whose inclusion rationale is documented across the upstream research manuals. Each row pins a specific computational step, algorithm variant, or industrial mechanism; a pedagogical baseline and an external reference for the exact same calculation share one row rather than inflating counts as two separate statuses.

Four mutually exclusive coverage statuses are used:

- **Runnable Local Baseline**: Backed by an in-repo pure-Python/NumPy pedagogical implementation, runnable example, and regression test—strictly within the stated assumptions of that row, without claiming a full paper system or commercial product.
- **External Reference Implementation**: Mapped to a verified official or author repository with pinned commit and license—dependencies, pretrained weights, datasets, or target hardware may still be absent, and documented upstream discrepancies may exist.
- **Principle Index**: Grounded in primary literature or formal derivations, without yet mapping to a unique, license-cleared source file implementing that exact computation (also used when public code lacks an established redistribution license, with the reason noted explicitly).
- **Explicitly Excluded**: A named generic software label lacks a unique algorithmic/repository identity or compatible license under our inclusion policy (without removing academic discussion of the underlying concept).

The algorithm matrix comprises **388 rows**: **102 Runnable Local Baselines**, **197 External Reference Implementations**, **88 Principle Index entries**, and **1 Explicitly Excluded entry**. Exercise mappings are counted separately below. Binaural beamforming adds one locally reproducible control row reusing our MVDR/LCMV solvers plus one pinned `openMHA` external reference row. Known-excitation per-bin regularized deconvolution shares a single row pairing our local numerical kernel with its `pyfar` external counterpart and bounded adapter audit; Chapter 6's known playback-gain step and tail-history controls reuse NLMS and NCC. Frontier Topics III and IV add local runnable numerical baselines covering parametric spatial capture, binaural signal matching, cross-modal anti-wind fusion, conditioned target extraction, near-field distance bubbles, spatial-spectral TS-VAD/GSS gating, and audio-visual asynchrony fallback. Note that a `Principle Index` status never implies runtime execution.

Upstream source checkouts and entrypoint checks are recorded in [`SOURCE_STATUS.json`](SOURCE_STATUS.json), where `not_run` in dependency/execution fields indicates that `fetch_upstreams.py` does not run external code. Actual runtime probes and numerical comparisons appear in the [Source Reproduction Manual](research_en/04_source_reproduction.md), the [AEC, WPE & Separation Manual](research_en/02_aec_wpe_separation.md), and the [standalone WPE comparison script](../ch07/examples/compare_wpe_reference.py). Bounded JSON contract reports for DOA, beamforming, WPE, separation, tracking, imaging, distributed arrays, and industrial interfaces sit in `codes/chapters/**/reports/`; executing a bounded probe against external `_downloads/` code never reclassifies it as an in-repo pedagogical baseline. Full commit hashes, official URLs, licenses, and source IDs live in [`SOURCES.lock.json`](SOURCES.lock.json). In-repo pedagogical paths below are relative to the repository root, whereas third-party internal paths are relative to each upstream repository root ("same file" inherits only the file path from the row immediately above, never its algorithm or verification scope).

Detailed signal models, source walkthroughs, and experimental designs appear in [Spatial & Tracking](research_en/01_spatial_and_tracking.md), [AEC, WPE & Separation](research_en/02_aec_wpe_separation.md), and [Industrial Deployment](research_en/03_industrial_deployment.md). Rows tagged "Research extension" do not imply full step-by-step derivations in the main chapter prose. Chapters 6–8 are organized into dedicated per-algorithm and per-engineering-task sections; section pointers below match current headings while keeping source acquisition and numerical execution logs distinct.

## How Unexecuted or Bounded Items Are Preserved

External Reference Implementations may exhibit compilation hurdles, library version incompatibilities, or algorithmic edge-case bugs: static index-shift issues in `CSSM`/`WAVES`/`TOPS` and live numerical WPE agreement must be read on their individual merits rather than treating repository counts as pass rates. Similarly, when an upstream repository publishes only a neural model backbone, our matrix records coverage of that architecture file rather than claiming training recipes, pretrained weights, or paper leaderboard tables.

`Principle Index` entries state explicitly what evidence would be required to promote them: a unique author repository, clear redistribution license, exact model config, or minimal in-repo derivation. Never downgrade license-cleared source code to "unimplemented" merely because a framework is large, copyleft, or omits weights—and conversely, never mark an entire algorithm family covered merely because one helper shares a similar name.
