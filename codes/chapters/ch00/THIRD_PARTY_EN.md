# Third-Party Implementations and Industrial Ecosystem Index

**[简体中文](THIRD_PARTY.md)**

This index catalogs **129 Git upstream repositories**, of which **112** have isolated local source checkouts under `codes/chapters/ch00/upstream/_downloads/`. On 2026-11-11, the binaural beamforming selection of `openMHA v4.18.1` was added; on 2026-11-17, 13 pinned pure-text source selections were added (`spharpy`, `sofar`, `spaudiopy`, `anf-generator`, `rir-generator`, `sc-wind-noise-generator`, `ci-sdr`, `py-motmetrics`, `oboe`, `p808`, `dasf-toolbox`, `wesep`, and `gtcrn`). Earlier core entries were verified on 2026-09-22, and RLS/Kalman AEC entries were verified on 2026-09-23 (`pyaec`, `PFDKF`, and `Subband_Kalman_AEC` fetched at pinned commits on 2026-09-24; `DiCoW v1` demo and `TS-ASR-Whisper v1` training sources fetched on 2026-09-28; humid-air speed-of-sound model added on 2026-09-30; `SAID` and `NeMo WPE` fetched on 2026-10-01; four `TAC` files fetched on 2026-10-02; and bounded selections of author `WOLA-DANSE`, `paderwasn`, `TI-DANSE+ batch`, 11 `CN-UPB/WASN` files, and 27 `LibriCSS` files fetched on 2026-10-04).

Offline verification checks every workspace item by item against both its sparse inclusion paths and all 32 excluded file extensions: **89 pass** (including `openMHA` and all 13 entries added on 2026-11-17), **22 legacy checkouts** carry the earlier 20-rule exclusion list and report `source_selection_mismatch`, **17 entries** are `index_only`, and **1 entry** (`aec-challenge`) retains 5 locally modified recordings as an honest verification failure. Legacy checkouts are neither rewritten nor overwritten automatically. Note that `pystoi` is a community-maintained Python implementation by its software author rather than an official Python release from the original STOI paper authors. Full verification statuses and commit hashes live in [`SOURCE_STATUS.json`](SOURCE_STATUS.json) and [`SOURCES.lock.json`](SOURCES.lock.json). Status reports are generated offline by `fetch_upstreams.py --verify`; passing source verification does not imply that an upstream project has been executed.

"Fetched" means an isolated upstream worktree exists locally under `_downloads/`; whether it matches the current pinned commit, clean worktree state, registered entrypoints, and 32-rule sparse policy is reported per entry in `SOURCE_STATUS.json`. Fetching source files does not imply installing dependencies, compiling binaries, training models, downloading pretrained weights, completing acoustic chamber tests, or obtaining commercial deployment rights. Complete entrypoints and caveats appear in `SOURCES.lock.json`; algorithm-level analyses, minimal experiments, and failure modes appear in the [Upstream Research Manuals](research_en/README.md).

## Official Upstream Sources and Intended Roles

`NumpyOnlineWPE011` inside `codes/chapters/ch07/examples/compare_online_wpe_reference.py` is a minimal NumPy adaptation of `nara-wpe 0.0.11`'s `OnlineWPE` and positive-matrix-inversion guard, preserving exact frame-buffer ordering and update rules strictly for version-equivalence auditing rather than independent mathematical proof. That adapted code retains the 2018 copyright notice of the Communications Engineering Group, Paderborn University and its [verbatim MIT license](../ch07/licenses/nara_wpe_MIT.txt), with provenance, modifications, and pinned version documented in the script header. This upstream MIT notice does not alter the dual-license terms of original files in this repository, and GPL spatial-processing references are invoked exclusively from isolated `_downloads/` directories without ever copying GPL code into our pedagogical packages.

Local C experiments for `SMP-PHAT` additionally compile single-precision static FFTW 3.3.10 as an external build dependency (neither counted as a separate spatial algorithm nor added to the Git repository lockfile). The official tarball [`fftw-3.3.10.tar.gz`](https://fftw.org/pub/fftw/fftw-3.3.10.tar.gz) has SHA-256 `56c932549852cddcfafdab3820b0200c7742675be92179e59e6215b340e26467`. Inside the tarball, `COPYRIGHT` and `kernel/alloc.c` specify `GPL-2.0-or-later`, whereas `api/fftw3.h` carries a separate 2-clause BSD header—never generalize the header's BSD notice to the compiled library as a whole. FFTW sources, licenses, and compiled artifacts remain strictly inside local isolated `/tmp` or ignored directories and are never distributed in Git commits; diagnostic reports log the exact linked library version and digest.

## How Local Upstream Sources Are Stored

`fetch_upstreams.py` processes only anonymous HTTPS URLs and full 40-character commit SHA-1 hashes registered in `SOURCES.lock.json`. Because `_downloads/` is Git-ignored, upstream sources sit locally under `codes/` for inspection without ever being pushed in repository commits; any reader can reconstruct the exact same isolated checkouts using the lockfiles and acquisition commands, with original upstream license files preserved inside each directory.

Fresh checkouts enable Git sparse-checkout to skip common audio, checkpoint, and archive extensions while disabling LFS smudging and recursive submodules. Extension filtering reduces binary downloads without guaranteeing that Git object stores or source files contain zero inline model parameters. Pre-existing full checkouts are preserved intact rather than overwritten or deleted for uniformity.

Whereas `fetch_upstreams.py` checks out only the primary WebRTC `src` repository, a separate isolated workspace synced build dependencies to compile `audioproc_f`—see the [Source Reproduction Manual](research_en/04_source_reproduction.md) for exact boundaries without conflating the two workspaces. Embedded targets (`CMSIS`, `SOF`, `TFLM`, `ONNX Runtime`) were not cross-compiled onto MCU/DSP boards; source-entrypoint verification is never conflated with hardware-in-the-loop qualification.

## Scope of Runtime Verification

[`SOURCE_STATUS.json`](SOURCE_STATUS.json) is emitted by the offline source verifier, where `execution: not_run` explicitly denotes that `fetch_upstreams.py` does not execute upstream code. Method-level numerical probes are logged separately—for example, [`compare_wpe_reference.py`](../ch07/examples/compare_wpe_reference.py) verifies valid-frame offline WPE arithmetic against `nara_wpe 0.0.11`, without certifying the entire `nara_wpe` package or perceptual speech quality.

Hardware audio pipelines must validate capture clocks, playback loopback references, ring-buffer watermarks, algorithm state machines, and output metrics sequentially. Real-time audio callbacks must never perform unbounded NumPy heap allocations, mutex locking, disk I/O, or socket calls; production systems details are analyzed in the [Industrial Deployment Manual](research_en/03_industrial_deployment.md) and [Source Reproduction Manual](research_en/04_source_reproduction.md).
