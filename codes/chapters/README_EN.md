Execute chapter modules from the repository root using Python's `-m` module runner, for example:

```bash
.venv/bin/python -m codes.chapters.ch00.chapter00_exercises
.venv/bin/python -m codes.chapters.ch04.chapter04_experiments
.venv/bin/python -m codes.chapters.appendix_b.appendix_b_experiments
```

All commands must be invoked from the repository root using the root `.venv` virtual environment. On a fresh clone, follow [Hands-On Reproduction in the Overview](../../chapters_en/00_overview.md#sec-u-6d43c0086f) to set up `.venv`, then run the 16 Chapter 0 mathematical foundation exercises and the three cross-chapter baseline suites. Those scripts print numerical verification results to `stdout` without generating or modifying audio files on disk. When reading output, match each metric to its input convention and constraint: `GCC-PHAT tau12 (samples): 3.0` indicates that channel 1 arrives 3 samples later than channel 2 (`187.5 μs` at `16 kHz`).

`DSB target response` and `MVDR target response` should be close to `1`, and STFT round-trip reconstruction error should sit near floating-point rounding precision. Extremely high matched noise-free AEC ERLE values verify arithmetic convergence rather than real hardware acoustics, while deadline misses in the queue simulation arise from synthetic burst workloads rather than live OS audio callbacks. Full step-by-step verification checklists appear in the Overview.

Legacy `codes.examples.*` and `codes.array_tutorial.*` import paths have been retired from internal interfaces. Always invoke the chapter modules listed in the table above; when updating an exercise, edit its single authoritative source file and synchronize all 352 stable exercise IDs, chapter prose, and `COVERAGE_EN.md`.

## Repository-Wide Code, Experimental Assets, and Reproduction Boundaries

The programs here turn textbook equations into minimal, inspectable experiments where tensor shapes, units, delay sign conventions, and edge cases can be verified step by step—they cannot be dropped in directly as a commercial real-time audio front-end. Real-time audio callback threads, OS drivers, thread scheduling, fixed-point optimization, pretrained model weights, and field array calibration still require the engineering layers detailed in Chapter 10. Input validation checks for obviously invalid dimensions or parameters, not production-grade defensive security.

The [Algorithm Coverage Matrix (`COVERAGE_EN.md`)](ch00/COVERAGE_EN.md) maps textbook methods to pedagogical code, unit tests, and external reference implementations, while the [Upstream Research Manuals](ch00/research_en/README.md) document source entrypoints, operating conditions, and executed experiments. When reading any implementation, inspect input/output shapes, angle origin, propagation delay sign, and steering-vector phase convention before comparing numerical values.

Several shared spatial/spectral modules use `(channels, freq_bins, frames)`, whereas WPE dereverberation and separation modules use `(freq_bins, channels, frames)`; transpose axes explicitly when passing tensors across modules. Numerical agreement on one deterministic example does not prove correctness for arbitrary inputs.

`ch00/` centralizes the [Chapter 0 mathematical foundation kernels](ch00/core/chapter00_math.py), [Chapter 0 exercise runner](ch00/chapter00_exercises.py), [cross-chapter exercises](ch00/cross_chapter/), [main 109-clip audio generator](ch00/examples/generate_audio_samples.py), [Git upstream lockfile](ch00/SOURCES.lock.json), [archive upstream lockfile](ch00/ARCHIVE_SOURCES.lock.json), [Git verification status](ch00/SOURCE_STATUS.json), and [archive verification status](ch00/ARCHIVE_SOURCE_STATUS.json). Status reports are generated offline by the [acquisition tools](ch00/upstream/README_EN.md); Git-ignored `_downloads/` checkouts may hold local modifications and must neither be overwritten nor committed.

## Real-Array Recording Exercise R01: Correlated Noise and Zero-Delay Averaging (`ch02/real_audio/`)

> Complete English translation of [`ch02/real_audio/README.md`](ch02/real_audio/README.md) (included here so `codes/chapters/ch02/real_audio/` preserves its exact 8-file directory membership enforced by `prepare_real_recordings.py --check` and `build_site.py`).

### R01 Problem Statement, Calculation, and Solution

Divide signed 16-bit PCM integers by `32768` to obtain digital amplitudes $x_m[n]$. Over $T = 160000$ samples, compute the **uncentered second-order moment** $R_{ij} = T^{-1}\sum_n x_i[n]x_j[n]$ rather than the mean-centered sample covariance. Evaluate the digital power of the first-$M$-channel sample mean and compare two expressions:

- **Retaining all cross-terms**: $P_{\mathrm{mean}} = M^{-2}\sum_{i,j=1}^{M} R_{ij}$.
- **Omitting cross-terms (diagonal-only prediction)**: $P_{\mathrm{diag}} = M^{-2}\sum_{i=1}^{M} R_{ii}$.

Notice that $P_{\mathrm{diag}}$ still retains each channel's actual power $R_{ii}$ without assuming equal channel gains; it matches the true mean power only when off-diagonal cross-terms are negligible. For signals with non-zero mean, statistical independence alone does not eliminate off-diagonal terms in an uncentered second-order moment matrix.

**Problem requirements**: Reproduce all quantities above for $M = 2$ and $M = 16$, read back the exported WAVs to compute $P_{\mathrm{PCM}} = T^{-1}\sum_n y_{\mathrm{PCM}}[n]^2$, and evaluate $10\log_{10}(P_{\mathrm{PCM}} / P_{\mathrm{diag}})$. Explain both the pre- vs. post-quantization difference and why these numbers cannot be interpreted as SNR gain.

| Quantity | 2 Channels ($M=2$) | 16 Channels ($M=16$) |
|---|---:|---:|
| Mean channel second moment $M^{-1}\sum_i R_{ii}$ | $1.1306449302\times 10^{-5}$ | $1.0971965890\times 10^{-5}$ |
| Diagonal-only prediction $P_{\mathrm{diag}}$ | $5.6532246512\times 10^{-6}$ | $6.8574786810\times 10^{-7}$ |
| Cross-term contribution $M^{-2}\sum_{i\ne j} R_{ij}$ | $1.0304891010\times 10^{-6}$ | $1.1240677806\times 10^{-6}$ |
| Pre-quantization mean power $P_{\mathrm{mean}}$ | $6.6837137521\times 10^{-6}$ | $1.8098156487\times 10^{-6}$ |
| Exported WAV readback power $P_{\mathrm{PCM}}$ | $6.6837332095\times 10^{-6}$ | $1.8098752073\times 10^{-6}$ |
| Readback power vs. diagonal prediction (dB) | `0.7272` | `4.2148` |
| Readback power vs. Channel 1 (dB) | `−2.2566` | `−7.9303` |

Power is measured in squared digital full-scale amplitude ($\mathrm{FS}^2$), not $\mathrm{Pa}^2$ or $\mathrm{dB\ SPL}$. For instance, at $M = 2$, $5.6532246512\times 10^{-6} + 1.0304891010\times 10^{-6} \approx 6.6837137521\times 10^{-6}$; values in the table are rounded only at the final step, with full precision stored in [`ch02/real_audio/MANIFEST.json`](ch02/real_audio/MANIFEST.json). Because sample-mean rounding introduces at most **0.5 PCM integer LSB** of error, readback power $P_{\mathrm{PCM}}$ differs slightly from pre-quantization power $P_{\mathrm{mean}}$.

In this excerpt, omitting cross-terms underestimates the averaged digital power—and as the channel count grows from 2 to 16, that discrepancy widens rather than disappearing. Nevertheless, because this recording contains neither separate target/noise components nor channel calibration, a drop in digital level cannot prove target preservation, speech quality improvement, or theoretical white-noise gain.

| `[7, 8)` | `0.2521` | `3.4738` |
| `[8, 9)` | `0.4841` | `3.3094` |
| `[9, 10)` | `1.3646` | `5.3188` |

These are observations from ten adjacent 1-second blocks of one continuous take—not ten independent trials, not a confidence interval, and not a characterization of all river recordings. Full-excerpt dB ratios must always be computed by pooling linear power across the entire `160,000`-sample window before taking $10\log_{10}$, never by averaging the ten per-block dB figures.

### Steps to Preserve When Recomputing R01

1. Decode the 16-channel interleaved `PCM16` data into a `(160000, 16)` integer array and cast to `float64` **before** squaring or matrix multiplication to avoid 16-bit integer overflow. Divide by `32768` to form the uncentered second-order moment; do not subtract channel means while comparing against the numbers above.
2. Average the first 2 or first 16 channels sample by sample, evaluating the diagonal-only prediction, theoretical pre-quantization mean power (with cross-terms), and exported readback `PCM16` power separately. Cross-check the off-diagonal sum via $P_{\mathrm{mean}} - P_{\mathrm{diag}}$.
3. Compute both numerator and denominator linear powers over the full `160,000`-sample record before applying $10\log_{10}$. Score the ten adjacent 1-second blocks individually rather than averaging block dB values into a full-excerpt metric.
4. Keep playback gain constant across the three mono listening files; never use automatic browser downmixing of the 16-channel file as a stand-in for 2-channel or 16-channel equal-weight averaging.

All figures here describe this fixed 10-second excerpt rather than clean speech/noise component ground truth. Published real environmental audio inside `codes/chapters/` consists solely of these four WAVs in `ch02/real_audio/` (paired AEC recordings in the ignored `_downloads/` cache belong to a separate local interface check and are not distributed on the website). Human listening sessions must be logged separately with listener, hardware, playback settings, file SHA-256, and observations; PCM power checks or browser loadability are never recorded as human-listening passes.

### Offline Verification and Re-Extraction

Because all four compact WAVs (`6,080,176` bytes total) are included in the repository, routine verification runs completely offline without modifying assets:

```bash
.venv/bin/python codes/chapters/ch02/examples/prepare_real_recordings.py --check
.venv/bin/python -m unittest discover -s tests -p 'test_codes_real_recordings.py' -v
```

Running `prepare_real_recordings.py` with no flags likewise executes read-only verification: checking pinned raw PCM SHA-256 digests, recomputing derived PCM waveforms, verifying WAV headers, and auditing every metric in `MANIFEST.json` (plus sample-for-sample verification against the upstream ZIP whenever present in the local cache; when the raw ZIP is absent locally, `--check` still detects any mismatch against pinned SHA-256 digests without claiming a fresh upstream re-download).
