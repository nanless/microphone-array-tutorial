## 1. Define the Reproduction Target First

Every reproduction effort must fix at least four elements: an algorithm, an implementation revision, an input configuration, and a well-posed evaluation question. Taking MVDR as an example, "reproducing beamforming" is too vague; instead, specify: "given a two-channel target steering vector and noise covariance matrix, verify that the computed weights satisfy the unit-gain distortionless target constraint and check that the output noise power matches the closed-form solution." Neural mask estimation, audio file I/O, and speech recognition backends can be wired in during subsequent experimental layers.

| Reproduction Layer | Required Inputs | Outputs and Acceptance Criteria | Conclusions That Cannot Be Drawn from This Layer |
|---|---|---|---|
| Formula | Small matrices, vectors, deterministic sequences | Matches hand calculations or independent analytical solutions | Effectiveness of the complete paper system |
| Module | Audio streams, sampling rate, configuration, cross-frame state | Preserves I/O contracts; fault-injection checks behave as expected | Real-time performance on hardware or end-to-end perceptual quality |
| Paper Experiment | Dataset splits, checkpoints, configurations, scorer versions | Reports metrics and deviations under the exact statistical protocol of the original paper | Equivalent performance in another room or array geometry |
| Device Pipeline | Hardware, drivers, firmware, reference tap point, clocks, power states | Continuous operation, latency, speech distortion, fault recovery | Coverage of every production scenario |

Distributed waveform enhancement additionally requires fixing node reference channels, broadcast dimensionality, filter update revisions, and shared sample-index labels. The pedagogical entry point is [Extended Topic II](../../../../chapters_en/13_distributed-enhancement.md), the actual upstream source execution scope is documented in [Pinned Distributed Source Contracts](#distributed-reproduction) below, and network clocking and bitrate protocols are covered in [Industrial Deployment §8](03_industrial_deployment.md#distributed-network-deployment).

## 2. Pinned Commits and Local Worktrees

The [lockfile](../SOURCES.lock.json) records official repository URLs and full Git commit hashes. The fetch utility checks out isolated worktrees, preserves upstream licenses and author notices, neither installs dependencies nor launches maintainer training or build scripts.

Run from the root of this repository:

```bash
.venv/bin/python codes/chapters/ch00/upstream/fetch_upstreams.py --list
.venv/bin/python codes/chapters/ch00/upstream/fetch_upstreams.py --all --report tmp/source-acquisition.json
.venv/bin/python codes/chapters/ch00/upstream/fetch_upstreams.py --verify --report tmp/source-verification.json
```

An existing local directory passes verification only when its remote origin, commit hash, working tree cleanliness, and required entry-point files all match the lockfile. If local edits or mismatched revisions are detected, the tool preserves the workspace state and reports an error; inspect the provenance of those edits before deciding whether to create a separate download directory. Never treat an incomplete checkout as a usable implementation.

Fresh downloads use Git sparse-checkout, skipping common audio, model-weight, binary-library, and archive file extensions. The fetcher neither initializes submodules recursively nor downloads Git LFS objects. This heuristic cannot filter every asset: plain-text files may still embed model coefficients, and the Git object store may retain upstream-tracked resources. Pre-existing local worktrees are left untouched, and their asset footprints are not retroactively guaranteed by newer exclusion rules. If a reproduction genuinely requires omitted files, consult the upstream project's asset documentation first and acquire them within an isolated environment following upstream instructions.

Local upstream checkouts live under `codes/chapters/ch00/upstream/_downloads/`, which is git-ignored by this repository. Commits to this textbook include only the fetch tooling and lockfile metadata, while each upstream worktree retains its original Git history and license.

## 3. Aligning Data Interfaces

Throughout this book, STFT, localization, and general covariance interfaces adopt the axis order `C × F × T` (channels, frequency bins, frames), whereas WPE and speech separation modules adopt `F × C × T`. Converting from the former to the latter uses `spectrum.transpose(1, 0, 2)`. External libraries may also use `T × F × C`. Equal dimension lengths can silently mask axis-order bugs; therefore, adapter layers must express axis permutations explicitly and test them on inputs with mutually distinct dimension sizes.

| Interface Aspect | Items to Record | Minimal Sanity Check |
|---|---|---|
| Time-Domain Input | Channel ordering, numerical scale, sampling rate, initial timestamp | Feed an impulse into one channel and silence into all others; check for channel permutation |
| STFT | Window function, window length, FFT size, hop size, center padding, one-sided spectrum rule | Run full analysis/synthesis round-trip and inspect interior error versus boundary transients |
| Delay and Phase | Cross-correlation sign convention, FFT sign convention, angle orientation, steering vector | Delay one channel by a known integer sample count; check sign and phase slope consistency |
| Covariance | Axis order, conjugation placement, frame-weight normalization, diagonal loading, power floor | Verify Hermitian symmetry, positive semidefiniteness, and scale equivariance |
| Beamformer Output | Reference channel, inner-product conjugation convention, per-bin scale | Verify target distortionless response and null depth toward a known interferer direction |
| Separation Output | Source count, permutation, scale projection/restoration, truncated length | Swap two known source estimates and confirm permutation-invariant scoring handles the swap |
| Online State | Previous-frame filter taps, noise power, recurrent network state, ring buffers, fractional phase | Compare streaming chunked execution against full-utterance execution; reinitialize state on every new stream |

The sound verification order is: check conventions first, verify objective functions second, and compare waveforms or perceptual metrics last. Differences in regularization floors and stopping criteria across library versions yield legitimate numerical discrepancies; report the root cause of such discrepancies rather than applying a single universal floating-point absolute tolerance blindly.

## 4. Designing Independent Experiments by Algorithm Family

### Localization and Beamforming

Start with a two-microphone array, a single plane wave, and noiseless input to verify directional conventions. Flip the angle of arrival from positive to negative, then swap the sensor ordering; the estimated direction must invert strictly according to the declared coordinate frame. Next, introduce one known directional interferer and separately inspect source-count assumptions, covariance rank, and search-grid resolution.

For MVDR/LCMV, plug small test matrices directly into the linear constraints. External implementations involving eigendecomposition allow an arbitrary unit-modulus complex phase factor on each eigenvector; consequently, comparing projection matrices, constraint residuals, or output noise powers is far better posed than comparing eigenvectors element-wise. Broadband methods additionally require auditing the mapping between physical FFT bin indices and working array indices—especially when frequency bands are pruned, sparse bins are subsampled, or a reference frequency is selected.

### AEC and Dereverberation

For AEC, begin with a deterministic short FIR echo path while retaining the exact playback reference, and partition the timeline cleanly into an initial convergence segment and a far-end single-talk scoring segment. Then introduce near-end speech, bulk delay, abrupt echo-path change, and loudspeaker nonlinearity one factor at a time. ERLE must neither misinterpret near-end speech during double-talk as residual echo nor compute echo attenuation over segments where the far-end reference is completely silent.

For WPE, verify the delayed prediction regressor vector, complex conjugation convention, and time-varying weighted normal equations first. Offline batch WPE and online frame-recursive WPE observe different frame supports and must not be expected to match sample-for-sample. When comparing implementations, record the prediction delay, filter tap order, covariance initialization, whether power estimation peeks at future frames, and any fixed bulk delay of the output relative to the reference channel.

### Blind Source Separation and Neural Systems

For blind source separation, verify scale restoration and frequency-permutation alignment on a known $2 \times 2$ mixture first, before varying source count, observation rank, or reverberation time. Whenever an iterative auxiliary objective is theoretically monotonic, verify monotonicity on that exact objective under identical normalization; never assume that a decrease in a surrogate contrast function guarantees a monotonic increase in SI-SDR.

Neural network systems additionally require pinning pre-trained parameter files (commonly called `checkpoint` files in source code), feature normalization statistics, recurrent/buffer states, chunk sizes, and target inference devices. The mere presence of a training script only indicates that a repository ships training code; without dataset access rights, exact hyperparameter configurations, and checkpoint revisions, one cannot claim that a paper's experimental results have been reproduced. When only architectural source files are fetched, state that boundary explicitly.

### Source Tracking and Engineering Pipelines

Test source trackers separately on constant-velocity trajectories, azimuth wrap-around boundaries, consecutive missed detections, crossing two-target trajectories, and false-alarm clutter. Tally data-association accuracy separately from angular localization RMSE; swapping track IDs between two crossing speakers can still yield a deceptively small average angular error. Particle filters require pinned random seeds and explicit documentation of effective-sample-size resampling thresholds.

Audio engineering interfaces must be tested at minimum under digital silence, full-scale overload, dropped frames, device hot-unplugging, sample-rate switching, and callback queue backlog. Offline file-based algorithm tests never substitute for real-time audio-callback thread tests. Streaming sample-rate conversion must preserve FIR filter history and fractional sampling phase across chunks; reinitializing the resampler per chunk introduces boundary clicks even when every individual chunk looks clean in isolation.

Event-scheduling boundaries also require independent analytical expectations. When service time equals arrival period exactly, completing a frame must release queue capacity immediately before admitting a frame arriving at the exact same instant; floating-point multiplication and accumulation rounding drift must not fabricate spurious frame drops. [Engineering Boundary Exercise E10-16](../cross_chapter/engineering_boundary_exercises.py) uses integer-tick hand calculations as ground truth alongside a genuine slightly-over-budget overrun control. Similarly, AGC gain-attack/release updates must be checked against closed-form recursions: when the smoothing factor equals 1, the updated gain must equal the target gain exactly; checking only that "the output is finite and unclipped" fails to catch erroneous muting caused by catastrophic cancellation.

External hardware timestamps and neural inference runtimes likewise demand protocol audits before benchmarking. [Industrial Deployment entries I01 and I18](03_industrial_deployment.md) inspect PortAudio callback timestamp semantics and ONNX Runtime device-buffer I/O binding and synchronization contracts, respectively. Exercise E10-17 executes synthetic timestamp subtraction and sample-index mapping, whereas the GPU I/O-binding comparison in I18 remains an experimental design; neither may be logged as a passed hardware benchmark merely because a runnable teaching script exists.

The 2026-10-01 [five pinned industrial source contracts](03_industrial_deployment.md#industrial-controlled-contracts) further separate "executing original upstream control flow" from "executing full production models." CMSIS compiles only the original scalar integer FIR and initializer; Speex invokes only four original noise-estimation helper routines; WebRTC VAD explicitly replaces the Gaussian classifier core with a deterministic routing counter; RNNoise replaces neural inference with an identity copy stub; and FastEnhancer replaces checkpoint loading, ONNX session inference, wall-clock timing, and WAV writing with inspectable deterministic boundaries. These contracts validate tap ordering, cross-block state continuity, legal frame lengths, head/tail sample counts, and RTF denominators—they do not measure ARM Cortex cycle counts, VAD classification accuracy, or perceptual denoising quality.

In this repository's closed-loop SRO teaching module, `fit_delay_ppm` invokes the [single canonical NumPy linear-regression kernel](../../ch10/core/engineering.py) directly inside the project `.venv`. It remains a controlled synthetic example with exact timestamps, constant clock drift, and analytically known waveforms; consolidating the implementation does not turn it into blind hardware clock-drift estimation. Historical JSON reports preserve the exact script paths, environments, and execution conditions recorded at the time they were generated.

### Engineering Interface Experiments and Planned Scoring Checks

Items 1 and 2 below have been executed, along with half-amplitude, chunked, and digital-silence gating checks for EBU R128 loudness. While pinned `pystoi` has undergone the controlled interface probes noted above, the full natural-speech scoring and failure-handling pipeline in Item 3 remains an experimental specification, and ViSQOL remains unexecuted. No natural-speech scores are pre-filled below.

1. **Streaming Sample-Rate Conversion**: Feed a 48 kHz stereo signal (a known impulse on channel 0 and a 1 kHz sine wave on channel 1), explicitly pinning float32 I/O, quality recipe, and single-threaded execution, downsampling to 16 kHz. Supply input as a single full buffer, in 127-frame chunks, and in 509-frame chunks, recording `idone/odone` on every call while carrying unconsumed input frames forward, and draining the FIR tail at end-of-stream.

    Compare valid output sample counts and aligned waveform differences under the exact same quality recipe, then run a mid-stream state-clear counterexample. In `libsoxr`, `soxr_delay` is denominated in output samples rather than milliseconds. Moreover, `soxr_oneshot` defaults to LQ whereas streaming `soxr_create` defaults to HQ; unless quality recipes are explicitly equalized, discrepancies reflect filter stopband/passband differences rather than streaming-state bugs. Fixed-ratio resampling checks also do not prove closed-loop clock-drift tracking. [Pinned `soxr.h` API](https://github.com/chirlu/soxr/blob/945b592b70470e29f917f4de89b4281fbbd540c0/src/soxr.h)

2. **Audio File Frames vs. Scalar Items**: Synthesize a 7-frame, 2-channel PCM16 file containing positive and negative impulses at distinct frame indices on left and right channels plus full-scale endpoints `−32768` and `32767`. Request 3 frames per read call and verify that returned counts follow `3, 3, 1, 0`; frame-based reads accumulate to 7 frames, whereas item-based reads accumulate to 14 scalar samples.

    Normalized floating-point readback in `libsndfile` divides signed 16-bit integers by `32768`, so the positive full-scale endpoint `32767` maps strictly below `+1.0`. Log both the read API mode and on-disk container subformat; never append unwritten tail slots of a caller buffer into the audio stream, and never misinterpret float readback as evidence that the underlying WAV file was encoded in IEEE float. [`libsndfile` API Documentation](https://libsndfile.github.io/libsndfile/api.html)

3. **Objective Scorer Failure Handling**: Pass aligned active speech, length-mismatched arrays, digital silence, and overly short active bursts to objective scorers. Inspect return values, runtime warnings, and failure causes; encode invalid evaluations as `null` accompanied by a machine-readable reason field rather than substituting `0` or minimum scores into corpus averages.

    When fewer than 30 active STFT frames remain after silence removal, `pystoi` emits a warning and returns `1e-5`; thus, merely receiving a finite float does not validate a score—validity must be gated on warnings and active-frame preconditions rather than hard-thresholding `== 1e-5` alone. Loudness `-inf` on digital silence must likewise be serialized distinctly. ViSQOL additionally requires pinning `speech` vs. `audio` mode, sample rate, and support-vector/lattice mapping model, never averaging scores across modes. [Pinned `pystoi/stoi.py` Implementation](https://github.com/mpariente/pystoi/blob/74872b000753a7a42ff51aa0868af8c82c7f9053/pystoi/stoi.py)

Because a negative value such as `−6.0` lies outside the representable range of `unsigned int`, C99/C11 classifies float-to-unsigned overflow as undefined behavior rather than modulo-$2^N$ wraparound; accidental behavior on one compiler/ISA pair provides zero portability guarantee.   "input": {"sample_rate_hz": null, "channels": null, "dataset_split": null},

Here `null` denotes an unpopulated experimental field rather than a measured zero. Research ledgers may legitimately retain `not_run` entries, whereas performance tables in the main chapters cite only fully specified, actually executed measurements. ### Appendix A: Least-Squares Fallback, Numerical Rank, and Physical Objectives

Even after a linear solver returns without raising an exception, two questions remain mandatory: does the returned vector optimize the intended physical objective, and does the destination array `dtype` preserve the numerical values computed by the solver? [Exercise E16-03 in Appendix A](../../../../chapters_en/16_appendix-symbols-math.md#sec-u-7b35821392) shows that zero residual does not imply parameter uniqueness, while [Exercise E16-05](../../../../chapters_en/16_appendix-symbols-math.md#sec-u-fc346cf32d) demonstrates that a minimum-norm least-squares solution to a singular covariance equation does not automatically solve constrained output-noise minimization. Algebraic solvability and physical optimality are distinct criteria that cannot be collapsed into "output is finite."

The [historical solver report](../../appendix_a/reports/upstream_solver_contracts.json) records an audit run on 2026-10-02 under Python 3.13.12 and NumPy 2.5.3 using [the bounded script revision at commit `241513c8`](https://github.com/nanless/microphone-array-tutorial/blob/241513c8f35d952747f16ccbb40cf85a5363b5ae/codes/chapters/appendix_a/examples/audit_upstream_solver_contracts.py). That audit loads the complete unmodified [`pb_bss/math/solve.py`](https://github.com/fgnt/pb_bss/blob/10acc347fc9ea21e3d312806a0bd751d0d0af183/pb_bss/math/solve.py) from pinned `pb_bss` commit `10acc347fc9ea21e3d312806a0bd751d0d0af183` and invokes `stable_solve` directly—performing zero AST extraction, source patching, or mock substitution, while avoiding top-level `pb_bss` package imports. That module is a general-purpose linear-algebra helper distributed by upstream maintainers under the [MIT License](https://github.com/fgnt/pb_bss/blob/10acc347fc9ea21e3d312806a0bd751d0d0af183/LICENSE), not a solver written by this textbook.

Upstream `stable_solve` attempts batched `numpy.linalg.solve` first; upon encountering a `LinAlgError`, it falls back matrix-by-matrix to `numpy.linalg.lstsq`. For $\mathbf A=\left[\begin{smallmatrix}1&1\\2&2\end{smallmatrix}\right]$ and $\mathbf B=\mathbf I_2$, letting $s$ denote the sum of the two entries in a solution column reduces column 1's squared residual to $(s-1)^2+(2s)^2$ with stationary point $s=1/5$, and column 2's squared residual to $s^2+(2s-1)^2$ with stationary point $s=2/5$. Splitting $s$ equally between the two identical columns minimizes Euclidean norm, yielding the exact analytical minimum-norm least-squares matrix $\left[\begin{smallmatrix}1/10&1/5\\1/10&1/5\end{smallmatrix}\right]$.

| Upstream Function Input | Observed Output or Classification | Boundary Illustrated |
|---|---|---|
| Singular $\mathbf A$ above, float $\mathbf B=\mathbf I_2$ | Matches analytical minimum-norm matrix within absolute tolerance $10^{-14}$ | Floating-point fallback branch satisfies the algebraic least-squares objective on this case |
| Same singular $\mathbf A$, integer $\mathbf B=\mathbf I_2$ | Returns all-zero integer matrix; logged as `observed_integer_fallback_truncation` | Fallback allocates output via `np.zeros_like(B)`, silently truncating fractional least-squares entries into integer `0` without warning |
| $\mathbf A=\mathbf I_2$, integer $\mathbf B=\mathbf I_2$ | Returns floating-point identity matrix | Integer RHS does not fail universally; here `linalg.solve` succeeded without entering the `zeros_like(B)` fallback |
| $\mathbf A=\operatorname{diag}(0,1)$, float $\mathbf B=[1,1]^\top$ | Least-squares fallback returns $[0,1]^\top$ | Algebraic $\mathbf A\vec w\approx\vec d$ solution is NOT the optimal MVDR weight vector for singular noise covariance |

The physical counterexample in the final row is derived analytically in this book: interpreting $\mathbf A=\operatorname{diag}(0,1)$ as a singular noise covariance matrix and $\vec d=[1,1]^\top$ as the target steering vector imposes the distortionless constraint $w_1+w_2=1$ with output noise power $|w_2|^2$. Choosing $\vec w=[1,0]^\top$ satisfies the unit-gain constraint with zero output noise power, whereas normalizing the least-squares direction $[0,1]^\top$ yields unit noise power `1`. Because this audit invokes only `stable_solve` rather than an upstream beamformer class, this objective-mismatch diagnosis must not be misquoted as an end-to-end MVDR pipeline run.

Two additional controls invoke `numpy.linalg.lstsq` directly and are tabulated separately from upstream `pb_bss` calls. With $\mathbf A=\operatorname{diag}(1,10^{-8})$ and $\vec b=[1,10^{-8}]^\top$, passing explicit `rcond=1e-6` reports numerical rank `1`, solution $[1,0]^\top$, and true residual norm $10^{-8}$; passing `rcond=1e-10` reports numerical rank `2`, solution $[1,1]^\top$, and zero residual. Both calls return an empty `residuals` array from NumPy because $\mathbf A$ is square ($M \le N$ returns empty residuals whenever rank $\le M$ or $M \le N$, per [NumPy 2.5 `linalg.lstsq` documentation](https://numpy.org/doc/stable/reference/generated/numpy.linalg.lstsq.html), verified 2026-10-02). Upstream `stable_solve` does not expose `rcond` to callers.

### WASN: Separating Clock-Drift Estimation from Known-Rate Resampling

From official [`CN-UPB/WASN`](https://github.com/CN-UPB/WASN/tree/9b2590eb104abcde2a35af52c74d64ce30bf5ae2) at commit `9b2590eb104abcde2a35af52c74d64ce30bf5ae2`, 11 plain-text files (`52411` bytes total) were fetched—covering `README.md`, root `LICENSE`, DXCP-PhaT estimation and wrapper modules, network topology configs, named-pipe I/O helpers, and resampling/simulation scripts under `sync_sed/system/`. The [root `LICENSE`](https://github.com/CN-UPB/WASN/blob/9b2590eb104abcde2a35af52c74d64ce30bf5ae2/LICENSE) is `Apache-2.0` (SHA-256 `c71d239df91726fc519c6eb72d318ec65820627232b2f796219e87dcf35d0ab4`); third-party runtime dependencies retain their own separate licenses.

When asynchronous recording nodes run off independent crystal oscillators, tiny sampling-rate offsets accumulate into a growing inter-node time shift over long recordings. An *SRO estimator* infers unknown clock drift from acoustic observations, whereas a *resampler* shifts interpolation instants given a specified rate ratio—their inputs and outputs are distinct. Here DXCP-PhaT locates the estimator code and pipe helpers illustrate inter-process framing; because DXCP's core math was neither audited line-by-line nor executed in this pass, file acquisition implies zero claims about estimation accuracy.

Inspecting [`resample.py::STFTResampler`](https://github.com/CN-UPB/WASN/blob/9b2590eb104abcde2a35af52c74d64ce30bf5ae2/sync_sed/system/resample.py) exposes a critical unit-and-sign contract: its `__init__` parameter `sro` is denominated in **ppm** and divided internally by `1e6`; whenever that constructor `sro` is non-`None`, any per-chunk `sro` passed to `__call__` is silently ignored. Moreover, upstream docstrings define positive constructor `sro` to **simulate** clock drift, meaning compensating a known $+x$ ppm drift requires initializing with `-x`. Always read actual source contracts—never assume a class named `Resampler` performs blind clock recovery.

Even more subtly, when constructor `sro=None`, the dynamic `sro` argument passed to `__call__(..., sro)` enters the phase-accumulation recursion **directly without dividing by `1e6`**. Consequently, dynamic `__call__` expects a **dimensionless fractional rate offset**: an `80` ppm offset must be passed as $80\times 10^{-6}$, NOT `80`. Passing the same numerical literal across constructor vs. per-chunk calls introduces a $10^6\times$ scale bug.

As a concrete dimensional check, `80` ppm corresponds to a fractional rate offset of $80\times 10^{-6}$; over `10` s at a nominal `16` kHz clock, accumulated sample drift reaches $16000 \times 10 \times 80\times 10^{-6} = 12.8$ samples. That calculation illustrates unit scaling rather than upstream execution; exact rate-ratio conventions, delay signs, and receiver time origins must always be verified per API. Self-contained runnable baselines appear in the Book Overview and [Chapter 13](../../../../chapters_en/13_distributed-enhancement.md).

Upstream [`sim_sro.py`](https://github.com/CN-UPB/WASN/blob/9b2590eb104abcde2a35af52c74d64ce30bf5ae2/sync_sed/system/sim_sro.py) feeds chunks into `STFTResampler` in a loop and writes to the output pipe only when the returned array is non-empty. Because `STFTResampler` buffers internal overlap history and `sim_sro.py` includes no explicit end-of-stream flush step, streaming deployments must account separately for chunk size, initial latency before first non-empty emission, steady-state buffer occupancy, and EOF tail draining—neither misdiagnosing initial empty returns as dropped packets nor forgetting buffered tail samples at stream end.

Reference transcripts, ASR hypotheses, word timestamps, stream channel IDs, and GLM normalization tables are all integral inputs to the scorer, whose output is `(word_errors, ref_words, WER)` rather than an enhanced waveform.
